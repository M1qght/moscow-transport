# Проверка checkout

Проверял 18 ноября 2026 года на Windows, Node 24.15.0 / npm 11.12.1.

Успешно выполнены:

- `npm run db:generate` — Prisma Client 6.19.0;
- `npm run db:migrate` — начальная SQL-миграция, включая CHECK-ограничения;
- `npm run db:seed` — демо-пользователи, направления, история и свежие отметки;
- `npm run typecheck` — API, Vue-шаблоны, seed и импортёр;
- `npm test` — 4 unit-теста;
- `npm run test:e2e` — 6 сценариев с настоящей PostgreSQL;
- `npm run build` — NestJS и production-сборка Vite;
- `prisma migrate diff` между локальной БД и schema.prisma — различий нет;
- HTTP-запросы к фронтенду и `/api/health` — 200;
- `git diff --check`, проверка исключения `.env` и `node_modules` из Git.

В браузере проверил поиск остановки, переключение остановки, вход admin123 с переходом на `/admin`, загрузку таблицы тикетов, отправку отметки и немедленный пересчёт текущей загрузки/прогноза. Проверил широкую и мобильную компоновку; скриншоты лежат в `docs/screenshots`. Автоматизированных browser e2e здесь пока нет.

При визуальной проверке выяснилось, что выбранный ранее CARTO endpoint отдаёт картинку «API key required». Слой заменён на стандартные тайлы OpenStreetMap; улицы и маркеры после замены проверены в браузере.

Docker Desktop в окружении не смог запустить engine. Поэтому локальные SQL/API-тесты выполнены на отдельном переносимом PostgreSQL 18.6 с loopback-портом 55432. Существующие базы и настройки Docker не менял. В compose и GitHub Actions настроен PostgreSQL 17; результат CI нужно смотреть в Actions, локальный тест на версии 18 не подменяет его.

Локальный `.env` (не в Git) на этой машине настроен на тестовый порт 55432. Стандартный `.env.example` рассчитан на Docker Compose и 5432. При запуске через compose скопируйте пример заново или замените порт в DATABASE_URL. Временная БД не является системной службой и не запускается автоматически после перезагрузки.

Первоначальная установка npm/Prisma прерывалась сетевыми ошибками. После загрузки зависимостей и официальных движков Prisma перечисленные проверки прошли. Онлайн-доступность городских источников и тайлов не гарантируется самим приложением.

Реальный `npm run data:import -- --osm` успешно импортировал 3040 остановок и 129 направлений. Загруженность не импортировалась. Поиск в интерфейсе обращается ко всей БД с задержкой 250 мс после ввода; лимит 1000 относится к одному ответу, а не к области поиска. Импорт JSON-экспорта data.mos.ru поддержан адаптером, но свежий экспорт городского портала в этой сессии не проверял.
